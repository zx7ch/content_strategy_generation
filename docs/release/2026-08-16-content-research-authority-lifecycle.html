规格设计审查：已证实缺口与待防范风险

前六阶段定义了研究含义、运行约束和结果事实；下列问题说明它们尚未完整覆盖“用户决策如何重新授权后续执行”。橙色为 Task 7 审查已证实的缺口，蓝色为由同一边界缺失引出的风险，不能当作已发生事实。

已证实：覆盖决策没有形成执行授权

  • 缺失对象：CoverageResolution 只记录用户选了 limited / expand / relax；它没有派生新的 ExecutionRevision（或 ScopeExecutionAuthorization）。
  • 直接后果：受限报告仅被读取，expand / relax 又调用已经完成的旧 dispatch，三条路径都不能可靠恢复治理或发布。
  • 规格修正：一个后端命令必须原子地写入用户决策、创建执行授权、推进/重排 dispatch；前端只能请求该命令并展示持久化状态。

已证实：读取投影遗漏 Draft 生命周期

  • 缺失状态：Scope 读取接口只投影已确认 Contract，不能返回“已准备、未确认”的 Draft。
  • 直接后果：用户刷新页面后，确认卡可能因 404 消失；草案仍在库中，UI 却无法恢复这个待确认动作。
  • 规格修正：Scope projection 必须显式返回 draft | confirmed | superseded，并携带 draft revision、可执行操作和确认所需的并发令牌。

已证实：前端在猜测允许的覆盖决策

  • 缺失契约：Coverage Snapshot 没有成为唯一的“允许何种决策、还缺哪项约束”的行动契约。
  • 直接后果：当仅缺样本量或作者数时，UI 仍可发 expand；请求没有 unmet constraint ID，后端必然拒绝，用户走入死路。
  • 规格修正：服务端投影 allowed_resolutions、每个 action 的必填参数和不可操作原因；UI 不再根据文案自行推断状态机。

已证实：异步读取没有运行归属保护

  • 缺失关联：异步 Scope / Report 读取缺少“当前 workflow_run_id + 请求序号”的归属校验。
  • 直接后果：旧 run 的慢响应可覆盖新 run 的界面状态，甚至把一个线程展示成另一个线程的 Scope 或报告。
  • 规格修正：每一份投影绑定 workflow run；客户端仅接纳仍等于当前 run 且请求序号最新的响应，后端也拒绝跨 run 的命令。

待防范：Scope 修订与补搜执行被混为一谈

  • 风险：若把每次补搜都错误地升级为 Scope v2，原本同一研究范围的详情、覆盖重算、报告缓存和 dispatch 回调会被人为分叉，审计与复用都会变复杂。
  • 需要写入规格：仅当用户改变研究含义（对象、条件、条件模式或最终 query 的语义）时追加 Scope 修订；补搜同一范围只创建 ExecutionRevision。所有候选、详情、Coverage、报告、dispatch 和幂等键绑定二者，跨 Scope 修订写入一律拒绝或隔离。

待防范：决定重试与多端并发缺少冲突语义

  • 风险：双击、断线重试、两个浏览器分别选择 expand / limited 时，可能生成重复执行或互相覆盖的结论。
  • 需要写入规格：Coverage 决策使用 action idempotency key、expected revision 和唯一 winner；冲突响应返回已生效的决策及其执行授权，而不是再次派发。

待防范：旁路入口可能绕过 Scope 与执行授权

  • 风险：旧 API、后台 worker、CLI 或报告端点若只检查“有 Contract”，仍可能绕过 coverage decision / execution revision 直接收集或发布。
  • 需要写入规格：列出所有采集、重试、治理、报告入口，并规定每个入口同时验证 active Scope Contract、Coverage 状态和对应的执行授权。

待防范：SQLite 的全局写竞争仍是横切风险

  • 现状边界：Scope 确认已采用专门的原子写入与锁冲突分类；这并不自动统一其它 sqlite3 / aiosqlite 写路径。
  • 风险：覆盖决策、dispatch 或审计若各自处理 busy / locked，可能留下重试语义不一致或部分成功的边界。
  • 需要写入规格：定义哪些命令必须单事务完成、哪些锁错误可重试、以及失败后返回何种可恢复状态；不要把事务编排散落在 service 层。
应补齐的权威链：Scope Contract（研究含义） + Coverage Snapshot（实际是否满足） + CoverageResolution（用户选择） → ExecutionRevision（系统可执行授权） → dispatch / governance / publication。前端只渲染该链的投影，不能自行拼接下一步。
